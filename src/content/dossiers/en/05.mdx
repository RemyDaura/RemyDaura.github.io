<Section label="Context" title="Forecasting prices, starting with the database">

The DATAImmo project aims to improve real estate price forecasting. The first phase is to design a database that consolidates raw property transactions (DVF, the French land registry dataset), INSEE population data and a geographic reference table.

</Section>

<Section label="Need" title="Three strategic needs">

Turn raw, scattered data into a decision support system able to meet three strategic needs: **valuation** (targeting luxury properties), **demographic pressure** (measuring market turnover), and **segmentation** (analysing price premiums by type of property).

</Section>

<Section label="Approach" title="From the data dictionary to window functions">

A data dictionary first validated the quality of the model: atomic variables, precise types, and above all confirmation that no personal data is stored, only transactional, statistical and geographic information.

The schema follows third normal form (3NF), with five cascading entities: SALE → PROPERTY → TOWN, completed by DEPARTMENT and REGION, so a property can be analysed at any geographic level without ever duplicating information.

Once the schema was validated, the tables were created in MySQL with particular attention to integrity: converting `date_mutation` to the DATE type (essential for reliable quarterly comparisons), enabling every foreign key, and creating an index on the most queried geographic column to speed up analytical queries.

Three queries then demonstrated what the database can do:

- a ranking of the 3 most expensive towns in each department, with a `RANK() OVER (PARTITION BY ...)` window function;
- a ratio of transactions per 1,000 inhabitants, to measure demographic momentum;
- a conditional aggregation (`AVG` with `CASE WHEN`), to compare the price per m² of 2-room and 3-room flats in a single query.

</Section>
