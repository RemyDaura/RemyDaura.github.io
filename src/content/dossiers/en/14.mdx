<Section label="Context" title="A live source, with no history">

<Columns>
<Column>

My previous projects started from a file that was already prepared. This one starts from a public feed that changes every ten minutes, and has to produce a reliable result every day without me touching it.

The feed is a snapshot: each update overwrites the previous one. No history exists unless you build it. And the data is imperfect: stations that stopped updating their prices, typos, missing fields.

</Column>
<Column>

<Callout title="Three questions to answer">

1. How is the price of each fuel moving, in France and in the Bouches-du-Rhône (Marseille area)?
2. Which departments are the most expensive compared with the national average?
3. Which stations around Marseille are the cheapest today?

</Callout>

<Section label="Findings" title="What the tests caught" intro="Problems I would not have spotted by eye, most of them on the very first day of data (30,470 prices).">

<Findings>
<Finding value="17" title="suspicious prices">For example E85 listed at €1.99 against a national average of about €0.90. Flagged by a warning test, excluded from the averages.</Finding>
<Finding value="4" title="stations with no department">Department recovered from the postcode. The `departement_deduit_du_cp` column keeps a record of the fix.</Finding>
<Finding value="16 → 5.6%" title="of prices discarded">A 7-day freshness threshold excluded too many valid prices. The actual age distribution set it at 30 days.</Finding>
<Finding value="×2 → ×1" title="deduplication verified">Two runs on the same day: the raw table keeps both readings, the marts keep only the latest one.</Finding>
</Findings>

<Section label="Technical choices" title="What I decided, and why">

| Choice | Why |
| --- | --- |
| Loading with a load job | The BigQuery sandbox forbids streaming and INSERT statements. A load job appends a whole file without touching existing data. |
| Marts rebuilt on every run | MERGE is not allowed in the sandbox, and the volume is small: a rebuild takes a few seconds. |
| Calculations in dbt, not in the visualisation tool | Weighted averages computed from exact sums, tested and reusable: no average of averages, no already-rounded values. |
| Configurable business rules | The freshness threshold is a dbt variable (`jours_max_depuis_maj`), changeable without touching the SQL. |
| External trigger | GitHub Actions' built-in scheduler did not start runs for this repository. Every morning, cron-job.org calls the GitHub API with a token limited to this one repository. |
| No key in the repository | Locally, authentication goes through gcloud. On GitHub, a service account restricted to BigQuery, stored in the secrets. |

</Section>
