<Section label="Contexte" title="Une source vivante, sans historique">

<Columns>
<Column>

Mes projets précédents partaient d'un fichier déjà préparé. Celui-ci part d'un flux public qui change toutes les dix minutes, et doit produire chaque jour un résultat fiable sans que j'y touche.

Le flux est un instantané : chaque mise à jour écrase la précédente. Aucun historique n'existe sans le construire. Et la donnée est imparfaite : stations qui ne mettent plus leurs prix à jour, erreurs de saisie, champs manquants.

</Column>
<Column>

<Callout title="Trois questions à résoudre">

1. Comment évolue le prix de chaque carburant, en France et dans les Bouches-du-Rhône ?
2. Quels départements sont les plus chers par rapport à la moyenne nationale ?
3. Quelles sont les stations les moins chères autour de Marseille aujourd'hui ?

</Callout>

</Columns>

<Section label="Découvertes" title="Ce que les tests ont trouvé" intro="Des problèmes que je n'aurais pas vus à l'œil, la plupart dès le premier jour de données (30 470 prix).">

<Findings>
<Finding value="17" title="prix suspects">Par exemple de l'E85 affiché à 1,99 € pour une moyenne nationale d'environ 0,90 €. Signalés par un test d'avertissement, exclus des moyennes.</Finding>
<Finding value="4" title="stations sans département">Département retrouvé grâce au code postal. La colonne `departement_deduit_du_cp` garde la trace de la correction.</Finding>
<Finding value="16 → 5,6 %" title="de prix écartés">Un seuil de fraîcheur de 7 jours excluait trop de prix valables. La distribution réelle de l'ancienneté l'a fixé à 30 jours.</Finding>
<Finding value="×2 → ×1" title="dédoublonnage vérifié">Deux runs le même jour : la table brute garde les deux relevés, les marts n'en gardent que le plus récent.</Finding>
</Findings>

</Section>

<Section label="Choix techniques" title="Ce que j'ai décidé, et pourquoi">

| Choix | Pourquoi |
| --- | --- |
| Chargement par load job | Le bac à sable BigQuery interdit le streaming et les INSERT. Le load job ajoute un fichier entier, sans toucher à l'existant. |
| Marts recréés à chaque run | MERGE est interdit dans le bac à sable, et le volume reste faible : reconstruire prend quelques secondes. |
| Calculs dans dbt, pas dans l'outil de visualisation | Moyennes pondérées calculées sur les sommes exactes, testées et réutilisables : ni moyenne de moyennes, ni valeurs déjà arrondies. |
| Règles métier paramétrables | Le seuil de fraîcheur est une variable dbt (`jours_max_depuis_maj`), modifiable sans toucher au SQL. |
| Déclencheur externe | Le planificateur intégré de GitHub Actions ne lançait pas les runs de ce dépôt. Chaque matin, cron-job.org appelle l'API GitHub avec un jeton limité à ce seul dépôt. |
| Aucune clé dans le dépôt | En local, l'authentification passe par gcloud. Sur GitHub, un compte de service limité à BigQuery, rangé dans les secrets. |

</Section>
